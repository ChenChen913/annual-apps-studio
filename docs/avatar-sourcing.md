# 头像与信息站图标核对手册

> 面向「AI 创作者与信息源」名录模板。记录 2026-11 这轮头像反复找错的原因、正确路径和落地方式，避免下一次再加人时重复踩坑。

## 一、为什么会找错

头像不是「搜到一张图」就能用。常见的四个陷阱：

1. **平台缓存与旧文章**
   - 搜索页、旧文章、第三方导航站经常缓存的是账号几年前的头像。
   - 例如 `宝玉AI`：GitHub `dotey` 仓库里还是旧的绿色 T 标；X `@dotey` 当前头像才是持剑人物。
   - 例如 `JavaGuide`：GitHub / 旧博客头像还是海边风景；公众号与知识星球当前头像已经是「书本 + 苹果 + JavaGuide」字标。

2. **同名或近名账号**
   - B 站「我是程序员小灰」当前是挥手浅色仓鼠；CSDN 旧文与历史头像里是另一版单只灰仓鼠。
   - 「程序员小灰」和「AI 小灰」不是同一个账号，不能拿后者的仓鼠图替代。
   - 用户口头的「程序员小辉」实际指名录里的「程序员小灰」，需要按名单实体核对，不能按字面新建一个人。

3. **把「候选设计」当成「已上线头像」**
   - 2026 年 1 月「程序员小灰」发过新 logo 候选投票，但候选图不等于最终头像。
   - 正确做法是回到 B 站 / 公众号当前头像，而不是把投票页里的 1 号、7 号直接拿来用。

4. **站点图标用 Simple Icons 的单色字形**
   - Simple Icons 的 `reddit` / `x` / `youtube` 是单色路径，放在白色圆底上会变成「黑色字标」，不是用户认识的官方彩色 App 图标。
   - 正确做法：Reddit 用橙色 Snoo，X 用黑底白 X 方形，YouTube 用红底白播放键；需要彩色原图或官方品牌资源，不要用单色图标凑。

5. **不同平台的「当前头像」并不一致**
   - `Draco正在VibeCoding`：GitHub 通用头像是旧图；公众号当前是绿色电路龙。
   - `刘小排r`：B 站头像是旧的海边风景；公众号当前是海边灯塔人像。
   - `葬AI`：网站 logo 是白字 `@葬AI`；小宇宙播客封面是紫底粉色人像。
   - 这类账号要以**用户实际订阅的平台**为准，至少以公众号 / 播客 / B 站当前资料页为准。

## 二、可靠核对流程

按下面顺序做，基本不会再返工：

1. **先确定实体与平台**
   - 确认名单里的显示名（含大小写、空格、简繁、生僻字）。
   - 确认用户主要从哪个平台认识这个人：公众号、视频号、B 站、小宇宙、X、GitHub。
   - 同名账号先看简介、代表作、链接，不要只看名字。

2. **优先取官方资料页的当前头像**
   - B 站：`api.bilibili.com/x/web-interface/card?mid=...` 的 `data.card.face`。
   - 公众号 / 视频号：当前文章页或账号资料页的头像，不从旧文章配图推断。
   - 小宇宙：播客节目页封面。
   - X：`unavatar.io/x/{handle}` 或 X 资料页原图。
   - GitHub：只作参考，仓库 README / 社交预览图通常不是当前头像。
   - B 站老师：很多人没有官方 B 站号，优先个人官网 / 学校官方页 / 公开职业照；课程条目用校徽或课程官方字标；搬运号头像只作线索，不作最终头像。

3. **看原图，不看搜索结果缩略图**
   - 下载后确认尺寸、是否裁切、是否带水印、是否是文字占位。
   - 人物头像统一裁成 512×512 WebP；站点图标保留透明底，按方形画布居中。
   - 低分辨率源图（如 168×168）可以用 LANCZOS + 轻量锐化，但要在 `creators_sources.json` 标出真实源尺寸。

4. **做一张联系表，肉眼逐个比对**
   - 把 66 张图排成 contact sheet，检查：
     - 是否有旧头像、重复头像、空白图；
     - 人物头像是否被裁掉脸部；
     - 站点图标是否是可识别的官方彩色版本；
     - 名字与头像是否对得上。

5. **写回三处，缺一不可**
   - `public/creators/*.webp`：实际使用的 512 图。
   - `src/data/creatorIcons.ts`：key → 本地路径映射。
   - `public/creators_sources.json`：`src`、`platform`、原图尺寸、裁切尺寸、备注。
   - 新增/替换后跑 `npm test`，确保映射文件都存在。

## 三、本轮已确认的修正

补充官号与播客时，也沿用同一套规则：

- **官号**：优先用品牌官方 logo / 官方资料页头像，不用搜索结果里同名的个人号或媒体转载图；子品牌要用自己的标识（如 TEG、腾讯云、晚点），不要全部拿腾讯总 logo 代替。
- **集团号 ≠ 子账号**：`腾讯科技` 不能拿腾讯集团的 `T` 或 `Tencent / 腾讯` 字标代替；`腾讯技术工程` 也不等于 TEG 品牌规范图，优先账号资料页当前头像。
- **播客**：优先用当前节目封面，不把主播个人照或节目嘉宾照当成节目头像；封面上的文字要与节目名对得上，源图小于 200px 时标注尺寸。

## 四、给下一次加人的检查清单

- [ ] 名字逐字对照用户给的写法，尤其是 `Xuan_酱`、`cxuanAI`、`JavaGuide`、`数字游牧人Samuel`、`Andrej Karpathy`。
- [ ] 先找当前资料页，再找旧文章；旧文章只用来确认身份，不用来取头像。
- [ ] 集团号不要用集团母 logo 代替；子账号优先账号资料页头像。
- [ ] B 站老师没有官方号时，用个人官网 / 学校官方页 / 公开职业照，不用搬运号头像。
- [ ] 头像源图 ≥ 200×200；低于 200 的要在来源 JSON 标注。
- [ ] 人物图裁成 512×512；站点图保持透明、方形居中。
- [ ] 站点图标必须是彩色官方版本，不用 Simple Icons 单色路径。
- [ ] 更新 `creatorIcons.ts` 与 `creators_sources.json`。
- [ ] 生成联系表人工过一遍，再跑 `npm test` / `npm run build`。
